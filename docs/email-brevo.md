# 邀请制邮件服务

## 普通用户

1. 克隆项目或安装应用即可使用看板，无需邀请码。
2. 在「提醒」填写自己的邮箱和邀请人提供的邀请码。
3. 云端验证通过后发送确认邮件；点击邮件中的按钮，并在打开的页面确认。
4. 回到应用点击「检查确认状态」。公共重置信号提醒由项目维护者的 Brevo 发件邮箱统一发送。
5. 需要个人每周恢复提醒时，在「我的额度」启用周邮件。取消、退订需要联网同步。

用户不需要 Brevo API Key、发件邮箱配置或 GitHub 管理权限。发信密钥和有效邀请码不在源码、安装包或前端中。

## 服务管理员

云端接口位于 [token-reset 的 service 目录](https://github.com/Brandon030722/token-reset/tree/main/service)。部署使用 Cloudflare Workers + D1 免费计划和现有 Brevo 发件账号，受各服务额度限制。

- 新建一份**不绑定任何公开表单**的 Brevo 专用名单。只有服务端完成邀请验证和邮箱确认后才能加入。
- 现有公开表单不能继续往实际发信名单中添加联系人。迁移时先部署新服务，再切换云端监控的名单，关闭旧表单。
- `INVITE_CODE`、`RATE_SALT`、`BREVO_API_KEY` 仅保存在服务端 Secrets。邀请码应使用至少 20 个字符的随机值；旧版已公开的邀请码失效。
- 发布时将服务地址写入 `public/config.json` 的 `mailServiceUrl`。仅该公开地址随应用分发，不包含任何密钥。
- 已确认用户的设备凭据保存在本机 `~/.tibo-reset/mail-session.json`（权限 600），只允许管理该邮箱的订阅和预约，不允许指定收件人或群发。

服务端每次预约和每次周邮件投递都会检查订阅资格。关闭界面、修改本地状态、复用旧版本地解锁记录均不能越过服务端检查。邀请码可被获邀者转发；本方案不能阻止持有人自愿分享，管理员可轮换邀请码停止新的注册。

## 提醒含义

广泛重置信号评分 ≥80 分时，公共云端按同一事件一次的规则提醒；它不是经过统计校准的 80% 概率。小范围公告仍走本机系统通知。个人周邮件按本机实际读取并同步的恢复时间预约，不证明额度已到账，不自行循环增加七天。云端每 15 分钟检查，实际投递可能延迟。

已提交或正在投递的邮件无法撤回。网络超时后的不确定投递记录标为 `needs-review`，不自动重发。接口受理也不代表收件箱送达。
